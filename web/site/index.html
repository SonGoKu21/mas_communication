THE STUDY AT A GLANCE

From disrupted messages to system-level consequences

We connect lower-stack communication anomalies to application-visible faults, trace their propagation through agent workflows, and distinguish intermediate consequences from final task outcomes. We then evaluate protection for two dependencies: executing the intended action and obtaining trustworthy information.

How to interpret the evidence

Composite success can require both an accepted evidence contract and a correct answer. A handling-response flag is not proof of a complete recovery chain. Repetitions are not controlled sampling seeds, and a single illustrative case does not explain an entire aggregate effect.

Detailed evidence is bundled for selected runs. Summary-only records are labeled explicitly. Source-mapping fixtures are not MAS task outcomes; frozen-evidence SWE/TAC runs are not fresh end-to-end benchmark executions.

What this artifact reproduces

This website replays archived evidence. It does not rerun an agent, execute a fault, or contact a model provider. Source identifiers link every record to an archived input file.

Task numbering

Task 001–100 identifies the 100 main-study tasks across models, topologies and repetitions. Original benchmark IDs remain visible. Shopping uses 001–030, Admin 031–050, Reddit 051–065, SWE-bench 066–085, and TheAgentCompany 086–100. The Reddit extension reuses these IDs; the separate protection study uses RQ4 Task IDs, and lower-stack tests use Fixture IDs. These numbers identify tasks or fixtures, not individual executions.

Reading the outcomes

Composite success follows the archived adapter endpoint; it can require an accepted evidence contract as well as a correct answer. Handling response is a recorded flag, not proof of a complete recovery chain.

Repeated executions are not controlled model sampling seeds. A missing consequence label is not proof that no propagation occurred.

Evidence availability

All verified records are indexed. Detailed exports cover representative condition/outcome groups, named case studies, all RQ4 runs, and fixture measurements. Other records expose only catalog fields and are labeled summary only.

URLs, credentials, email addresses and private deployment paths are redacted. Event lists preserve source order. Separate fault logs are not assigned to conversation steps without recorded links.
